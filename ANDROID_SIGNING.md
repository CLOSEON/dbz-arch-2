# Google Sign-In on Android — signing certificate mismatch

**Status: blocking. Fixed in the Firebase console, not in this repository.**

## Symptom

The app launches, the login screen renders, and tapping **Continue with Google**
shows:

> No credentials available

## Cause

Google Sign-In authorises on the pair **(package name + signing certificate
SHA-1)**. The certificate signing builds from this machine is not registered in
Firebase, so Credential Manager finds no matching OAuth client.

| | SHA-1 |
|---|---|
| Registered in `android/app/google-services.json` | `17:9F:F8:17:46:80:FD:FE:AF:14:6E:9C:A8:5B:55:1F:01:A2:DF:25` |
| This machine's `~/.android/debug.keystore` | `CC:65:C6:B3:2F:65:94:A4:44:1E:68:A1:D7:C2:5C:A4:AD:FC:44:ED` |

The registered fingerprint belongs to a different machine — most likely the
workstation the project was originally set up on. Every debug keystore is
generated locally and is unique, so this mismatch is expected the first time a
new machine builds the app.

Note the error message is misleading: "No credentials available" is also what
you get when the device has no Google account at all, which sends you looking
in the wrong place.

## What is NOT the problem

Both were checked and are correct:

- `default_web_client_id` **is** generated by the google-services Gradle plugin
  and **is** present in the shipped APK resources.
- `com.dabzo.app` has both an Android OAuth client (`client_type` 1) and a web
  client (`client_type` 3) in `google-services.json`.

## Fix

1. Get this machine's debug SHA-1:

   ```bash
   keytool -list -v -keystore "$USERPROFILE\.android\debug.keystore" -alias androiddebugkey -storepass android -keypass android
   ```

2. Firebase console → Project settings → Your apps. For **each** of the four
   Android apps — `com.dabzo.app`, `com.dabzo.vendor`, `com.dabzo.rider`,
   `com.dabzo.admin` — choose **Add fingerprint** and paste the SHA-1.

3. Download the updated `google-services.json` and replace
   `android/app/google-services.json`.

4. Rebuild:

   ```bash
   npx cap sync android
   node scripts/build-all-apks.mjs
   ```

A fingerprint can be added per app without disturbing the existing one, so the
original machine keeps working.

## Separately: vendor, rider and admin

Only `com.dabzo.app` currently has an **Android** OAuth client at all. The other
three have a web client but no `client_type` 1 entry, so Google Sign-In will
fail on them even once this machine's SHA-1 is added to `com.dabzo.app`. Adding
the fingerprint in step 2 to all four apps creates those entries.

## For release builds

A release keystore has its own, different SHA-1. It must be registered the same
way before Google Sign-In works in a store build — this is not carried over from
the debug fingerprint.
